# Supplier Business Code Implementation Plan

> **For agentic workers:** Implement inline with superpowers:executing-plans; TDD and independent review before deployment.

**Goal:** Add stable NCC-001 style supplier codes without changing UUIDs, historical documents, snapshots or stock.

**Architecture:** One additive migration adds a nullable unique `inbound_suppliers.code` and initializes only missing codes in name/id order. Existing assigned codes and all old supplier fields stay unchanged. The current P04 supplier GET adds code, display_name and code_status while preserving id/name/version, ACL and pagination. No write endpoint or historical projection is changed.

**Tech Stack:** Laravel/PHP, PostgreSQL and SQLite, existing Docker DEV deployment.

**Spec:** User approved existing supplier code allocation, preserve UUIDs/history, test and deploy DEV/TEST; asked explicitly about avoiding data loss.

## Constraints

- No migrate:fresh, seed, delete, reset, automatic DB restore or production action on the served DB.
- Only the new migration may run on DEV, not an unbounded migrate-all.
- UUID/name/status/version/created_at/updated_at unchanged; existing pending supplier selections remain valid.
- No code copied into old RECORD snapshots; old name values are not concatenated or repaired.
- API fields code/display_name are read-only; RECORD continues existing supplier_id/version input.
- Preserve active runtime overlay087e (eight P06/P18 files over shared d249); imported byte-for-byte into canonical source because its label is not reachable in the shared BE repository.
- Keep Auth v1, delivery/selftest/canary and all other runtime flags exactly unchanged. No operator login/revoke or push TEST.
- No hosted/automatic CI activation. Candidate tests/audits do not close old GoLive approval gates.
