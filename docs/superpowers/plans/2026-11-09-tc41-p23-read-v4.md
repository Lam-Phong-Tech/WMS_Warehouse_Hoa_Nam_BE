Baseline: deployed/shared db6e9050ae68b2e20579b7e92c3f6215e59ce6c9,
DEV schema231. User requests read-only TC41 completion, not TC40/production.

- Keep header-free P23 v3 and P08 wire behavior. Negotiate v4 explicitly with
  X-Scan-Session-Contract=mini-app-p23-read-v4 on the existing two GET routes.
- Reuse current auth family/history.read/inventory.view/confirmed warehouse,
  tenant isolation, dedup, cursor and read-only single-response snapshots.
- Bind both list/detail cursors to the chosen representation. Do not accept a
  v3 cursor in v4 or derive counts/latest from the visible page.
- Field values have explicit source/status. Batch creator is not event actor.
  Names are persisted historical snapshots only; never current IAM names.
- Raw code is not broadly opened: inventory.trace plus strict safe identifier
  format; unstructured/PII/secret/URL values remain redacted even when permitted.
- Verified valid codes are distinct persisted identities from ACCEPTED, or
  canonical VALID with a verified owner event relationship. RESOLVED is not
  ACCEPTED. Explicit rejection and duplicate attempt totals are separate.
- Link only exact event -> owner row -> line -> document/case, same warehouse and
  tenant plus owner read rights. Batch source_id alone never yields a GET link.
- Component issued quantity requires POSTED owner, timestamp, posted item/event
  identity and matching negative owner ledger; otherwise null with reason.
- Existing DEV batch tables lack batch_no/started_at/ended_at/status. Historical
  values stay null; do not add fictional values or a backfill migration.
- Prefer existing TEST data for live inspection; no new business documents,
  stock effects, seed, grant or operator login to manufacture UAT evidence.
